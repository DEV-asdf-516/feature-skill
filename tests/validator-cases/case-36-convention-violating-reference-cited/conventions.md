# 프로젝트 컨벤션
## 1. 설계 원칙
- 1.1 Tell, Don't Ask — Service 는 값 객체·엔티티의 상태 필드를 꺼내 그 값으로 분기하지 않는다. 그 상태에 따른 판단·생성은 상태를 가진 객체의 메서드(또는 정적 팩토리)가 맡고, Service 는 그 결과를 받아 쓴다.
- 1.2 흐름 제어에 boolean 플래그 지역 변수를 쓰지 않는다. 조건이 깨지는 지점에서 즉시 예외를 던지거나 반환한다(guard). 기존 코드 중 플래그를 쓰는 곳은 legacy 이며 새 코드의 근거로 삼지 않는다.
